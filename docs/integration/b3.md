# openbot-b3

消费者：`integrations/openbot-b3`。

本地 stand-in：`POST /v1/device/tools:invoke`（B3）。它调用 A3 设备工具目录，不直接碰硬件。

可以组包或查询的工具：

| 工具 | 作用 |
|---|---|
| `voice.abort` | 组固件 abort JSON，不清本地队列 |
| `voice.listen.start` / `voice.listen.stop` | 组 listen JSON |
| `voice.wakeWord` | 组 `state=detect` |
| `mcp.forward` | 原样包一层 `type=mcp` |
| `media.describe` | 返回屏、摄像头和表情能力，不拍照 |
| `emotion.map` | 按固件 21 个名字收成 6 类，并给出 chat 路径 |

`ota.flash`、`ota.massFlash`、`system.reboot` 会抛错。固件下行里确有 `{"type":"system","command":"reboot"}`，`describeSystemRebootCommand()` 只描述它，`executable` 为 false。`camera.capture` 不走固件抓帧，只走实验媒体闭环，见 [lab-camera.md](../lab-camera.md)。`media.describe` 仍然只描述摄像头，不拍照。

`assistant.tts` 只把 `assistant.visible.speech` 放进 `sentence_start` 报文。`assistant` 的其他键，包括 `visible` 里除 `speech` 以外的键，都不会进报文。没有 `visible.speech` 就失败，不会改念 `voiceId` 或别的字段。相同 `idempotencyKey` 只有在设备、`authorizationRef`、`bindingVersion`、会话和请求摘要都一致时才复现第一次的结果。键相同但内容不同会冲突，不会把上一次的结果当成这一次的。返回缓存结果之前会先检查吊销和当前绑定。

这是本地 stand-in。当前针是 main 上的 `bc3d9fda20f1806b6f47be4607ed4fdcc2fa4c9a`。OpenAPI 已入库，但这条工具路径仍是实验室 stand-in，不是 vendored 的 device-tool-requests。`41b75612…` 已作废，不是 `officialMergeSha`。

表情路径：

- 数字人：`system/emotion/{category}.eaf` 或 `.sjpg`，类别只有 crying、happy、loving、neutral、surprised、thinking
- 聊天：`system/chat/{emotion}.eaf`，非法文件名落到 `neutral`
