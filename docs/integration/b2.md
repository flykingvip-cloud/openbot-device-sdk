# openbot-b2

消费者：`integrations/openbot-b2`。

本地 stand-in：`POST /v1/device/sessions`（B2）。请求体只用冻结字段名：

- `authorizationRef`
- `bindingVersion`
- `digitalHumanId`
- `deviceId`

四项必须和当前绑定一致，包括版本号。rebind 之后旧的 `authorizationRef` 不能再开会话。响应带回绑定里的 `assistant.*`，不重命名、不删键。

同一把仍有效的 `idempotencyKey` 再开一次，返回原来的 `sessionId`。设备上已有未关闭的会话而键不同，返回 `SESSION_BUSY`。事件用 `eventId` 去重，重复提交不增加游标。会话游标默认 5 分钟。

`revoke`、`rebind`、`release` / `invalidate`，以及游标到期，都会关掉旧会话。append、pull 和再次打开（resume）会重查当前绑定的 `authorizationRef`、`bindingVersion`，以及设备是否已吊销。关掉之后，迟到事件不能再写入旧 run。rebind 完成并带上新资料后，可以为新绑定再开一个会话，不会因为旧会话而得到 `SESSION_BUSY`。到期的第一次 pull / append 得到 `CURSOR_EXPIRED`。

这些码是本地 stand-in 的消费者约定。正式针已经是 main 上的 squash merge，但本环境读不到该提交，所以没有把这些路径说成已发布 API。不要对 `upbeyond/openbot` 或作废针 `68e062e` 发会话请求。
