返回 `digitalHumanId` 和原样的 `assistant.*`。同一数字人的多条绑定如果 `assistant` 不一致，stand-in 会失败，避免悄悄改字段。

## Live stub

设置 `OPENBOT_DEVICE_DH_STUB_URL` 后，`readDigitalHuman` 改为请求：

`{origin}/api/integrations/v1/digital-humans/{digitalHumanId}`

`GET /healthz` 仍在 origin 根上。service Basic 和 `X-OpenBot-Grant-Credential` 都设置了才会附在这个 GET 上。样例客户端在 openbot-vp 的 `docs/integrations/device-digital-human/staging.md`，用法见 [live-stub.md](../live-stub.md)。响应里如果带了 `authorizationRef`，就按冻结绑定整包校验。没设置 stub URL，或没设置这对凭证时，`npm test` 里的 live 用例跳过，不访问网络。
